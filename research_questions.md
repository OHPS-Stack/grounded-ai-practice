# Grounded AI Practice — Research Questions

## Document status

Research-stage working document.

These questions guide early investigation. They do not assume that the project’s
current problem statement, audiences, learning model or proposed outputs have
already been validated.

## Immediate research priorities

The first research phase should answer five connected questions:

1. What practical AI capability gap is sufficiently evidenced to justify this
   project?

2. Which audience should Grounded AI Practice serve first?

3. What should that audience be able to do after completing an initial learning
   pathway?

4. Which learning methods are most appropriate for developing those capabilities?

5. What should the project build first to test these assumptions?

## 1. Problem and evidence

- What reliable evidence exists about AI use, understanding and capability in
  the UK public, education and workforce?

- Which problems are caused by lack of AI knowledge, and which are instead
  organisational, economic, technical or cultural?

- How common are unsafe, ineffective, costly or over-dependent forms of AI use?

- Where are the strongest documented gaps between AI adoption and responsible
  implementation?

- Which current project claims are supported by evidence, and which remain
  personal observations or hypotheses?

- How quickly is the relevant evidence changing?

## 2. Audience and need

- Which groups have a clear unmet need for practical AI learning?

- Which group would benefit most from the project’s local, cloud and hybrid
  perspective?

- What prior knowledge, resources, time and technical confidence can reasonably
  be expected?

- What problems are potential learners actively trying to solve?

- What barriers prevent them from using existing learning resources?

- Should the first audience be individuals, educators, employees, small
  organisations or another more specific group?

## 3. Practical AI capability

- What does “practical AI capability” mean for the initial audience?

- Which knowledge, skills, behaviours and judgement should be treated as core?

- Which capabilities are transferable across tools and model providers?

- Which capabilities are role-specific or technically advanced?

- How should responsible use, evaluation, privacy, security, cost and human
  oversight be represented?

- What observable tasks could demonstrate competence?

- Which capabilities should be prerequisites for local AI, RAG, MCP, agents or
  automation?

## 4. Learning design

- Which recognised learning frameworks are suitable for this project?

- When are project-based, experiential or competency-based approaches most
  effective?

- How should explanations, worked examples, guided practice, independent
  practice and reflection be sequenced?

- How should learners receive feedback and verify their understanding?

- How can the project support different starting points without becoming
  fragmented or overwhelming?

- What level of personalisation is genuinely useful?

- How should misconceptions, unsafe practices and overconfidence be addressed?

## 5. Comparable products and programmes

- How do roadmap.sh, LeetCode and comparable learning systems define progression,
  prerequisites and completion?

- Which design patterns improve clarity, motivation and sustained participation?

- How do existing AI-literacy and digital-skills programmes combine theory,
  practice and assessment?

- Which audiences and needs are already well served?

- Where do existing products appear incomplete, inaccessible or overly
  tool-specific?

- Which features should Grounded AI Practice learn from without imitating the
  product as a whole?

## 6. Technical and conceptual scope

- Which AI concepts are necessary for informed everyday and workplace use?

- When does hands-on local AI provide educational value beyond using a cloud
  application?

- Which tasks are better suited to local, cloud or hybrid processing?

- How should prompting, context engineering, retrieval, memory, MCP, agents and
  automation be taught as distinct but connected concepts?

- What security, privacy and trust boundaries must learners understand before
  connecting models to files, tools or external services?

- How much technical depth is appropriate for the first pathway?

- Which tools should be examples rather than permanent project dependencies?

## 7. Delivery format

- What is the smallest useful public output that could test the project’s core
  assumptions?

- Would the initial audience benefit most from a roadmap, guide, course,
  repository, website, guided build or another format?

- Which content should be linear, modular, searchable or interactive?

- What should be available without installing software?

- Which parts require practical exercises or a working technical environment?

- How should Word, web and GitHub outputs relate without becoming duplicate
  authorities?

- What accessibility requirements should shape the format from the beginning?

## 8. Information and knowledge architecture

- What information must be easy for a person to find without AI assistance?

- What structure best supports both human navigation and machine retrieval?

- Which material belongs in prose documents, structured metadata, tables or a
  database?

- When would Markdown, DOCX, YAML, JSON, CSV, SQLite or a vector index provide
  genuine value?

- What metadata is needed for status, provenance, review and retrieval?

- How should superseded information remain traceable without confusing current
  users?

- How can duplication and contradictory guidance be detected?

- What should remain outside any AI project knowledge base?

## 9. Evaluation

- How will the project determine whether learners have gained practical
  capability rather than merely completed content?

- What evidence would indicate that a learning pathway is understandable,
  useful and safe?

- How should factual accuracy, technical correctness and educational quality be
  reviewed?

- What should be tested through learner feedback, practical exercises or
  prototypes?

- Which project claims would need stronger evidence before public release?

- What would justify narrowing, changing or abandoning the current direction?

## 10. Sustainability and public presentation

- Is the project intended to remain personal and open, become community-led or
  support future commercial work?

- What contribution model would be appropriate for GitHub?

- What licensing, attribution and source-use rules will be needed?

- How can the repository demonstrate credible research, technical skill and
  reflective practice to prospective employers?

- Which outputs should be polished portfolio pieces, and which should remain
  internal working material?

- What level of maintenance can realistically be sustained?

## Research discipline

For each material finding, record:

- the question being investigated;

- the source and checked date;

- what the source directly supports;

- any inference drawn from it;

- limitations or conflicting evidence;

- the effect, if any, on the project direction.

Research should reduce uncertainty before it creates new rules, structures or
deliverables.
