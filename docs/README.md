# The landing site

This folder is the project's public landing site, served by GitHub Pages
from `/docs` on `main` and intended to also answer for
`groundedaipractice.co.uk` once the domain is pointed at it (a separate,
per-item decision — see `project_log.md`). It is a static, single-page
site: no build step, no framework, no JavaScript.

Everything here is self-contained. The logo files are copies of the
canonical exports in `assets/logo/`; the figures are generated by
`tools/build_site_figures.py` from data transcribed out of
`research_log.md`, with the entry numbers recorded next to the data in
that script. If a figure's numbers change, correct the constant and
re-run the script — never edit the SVGs by hand.

```
python tools/build_site_figures.py --og
```

The web fonts in `fonts/` are subsets of Public Sans, built from the
locally installed faces by `tools/build_site_fonts.py`; the SIL OFL
licence text ships alongside them as `fonts/LICENSE.md`, and the build
refuses to run without it. The stylesheet lists `local()` sources
first, so a visitor with Public Sans installed downloads nothing. The
figures are `<img>`-embedded SVGs and render in the viewer's installed
fonts by design — browsers do not fetch external fonts for documents
embedded that way.

```
python tools/build_site_fonts.py
```

## Security posture

The site's main defence is having almost no attack surface:

- **No JavaScript, no cookies, no third-party requests.** Every asset is
  served from the same origin, including the type: Public Sans is
  self-hosted as subsetted WOFF2 rather than loaded from a font CDN.

- **Content-Security-Policy via `<meta>`**: `default-src 'none'` with
  `img-src`/`style-src`/`font-src` limited to `'self'`, plus
  `base-uri 'none'` and `form-action 'none'`. Inline styles and scripts
  are not permitted by this policy, so none are used in the pages.

- **Referrer-Policy `no-referrer`** via `<meta>`, so outbound clicks leak
  no URL data.

Honest limits, because GitHub Pages serves static files and [does not
support custom response
headers](https://github.com/orgs/community/discussions/54257):

- **No `frame-ancestors`** (clickjacking protection): MDN documents that
  this directive is ignored when CSP is delivered by `<meta>` tag, and a
  header cannot be set on Pages. The risk is low for a content-only site
  with no logged-in state or actions to hijack, but it is a real gap.

- **No HSTS, `X-Content-Type-Options` or `Permissions-Policy`** for the
  same reason. "Enforce HTTPS" in the repository's Pages settings covers
  the transport-redirect half of what HSTS would do.

If the site later moves to a host that allows response headers
(Cloudflare Pages, Netlify, nginx), add:

```
Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

and remove the two `<meta http-equiv>`/`<meta name="referrer">` tags in
favour of the headers.

## Custom domain, done in the safe order

Configuring `groundedaipractice.co.uk` is three steps, and the order
matters because an unverified domain pointed at Pages can be [taken over
by someone
else](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)
if it ever comes unlinked:

1. **Verify the domain first** (GitHub account settings → Pages →
   verified domains): add the TXT record GitHub specifies at the DNS
   host, wait for propagation, verify — and keep the TXT record in place
   afterwards.

2. **Point DNS**: apex `A` records to GitHub's Pages IPs (and optionally
   `www` as a `CNAME` to `ohps-stack.github.io`), per GitHub's current
   documentation.

3. **Set the custom domain in the repository's Pages settings and tick
   "Enforce HTTPS"** once the Let's Encrypt certificate has been issued.
   Then update `canonical`/`og:url`/`og:image` in `index.html` to the
   domain.

## Accessibility

Semantic landmarks, a skip link, one `h1`, headings in order, alt text
carrying each figure's data, and focus-visible outlines. Both themes are
checked against WCAG 2.1 AA contrast by `tools/build_site_figures.py`,
which audits every palette pair the figures and pages rely on and fails
the build if one drops below threshold. Dark mode follows the visitor's
own `prefers-color-scheme`; there is no toggle, because that would need
JavaScript the site otherwise has no reason to carry.
