# The landing site

This folder is the public landing site. GitHub Pages serves it from
`/docs` on `main`, and the same files will answer for
`groundedaipractice.co.uk` once the domain is pointed at it. That step
is a separate decision, recorded in `project_log.md`. Plain HTML and
CSS. No framework, no JavaScript.

**The HTML in this folder is generated.** Pages are assembled from
`site/` by `tools/build_site_pages.py`, which holds the header, nav and
footer in one shared layout instead of copying them into every page.
Edit the layout and fragments in `site/`; anything changed here is lost
at the next build. The exception is `404.html`, which uses no shared
shell and is still maintained by hand.

Everything the pages load lives in this folder.

- The pages themselves are built from `site/layout.html`,
  `site/pages.json` and the fragments in `site/pages/`. The build
  refuses to write anything unless every page passes its checks,
  including that every link and every `#anchor` resolves to something
  that exists.

- The logo files are copies of the canonical exports in `assets/logo/`.

- The icons are copies from `assets/icons/`. The originals are the
  source of truth; re-copy rather than editing here.

- The data figures and the 404 mark are generated by
  `tools/build_site_figures.py`, from data transcribed out of
  `research_log.md` with the entry numbers beside the constants. To
  change a number, correct the constant and re-run. Never edit the
  SVGs.

- The claim-verification flow and the system diagram are ordinary HTML
  in `index.html`, built from the icon set. They carry no data, so
  nothing generates them.

- No terminal replica is shown at present. One was tried in the system
  section and removed: a contrast-audit window asked the reader to do
  technical work in the middle of an argument about small firms. The
  asset and its sync tool (`tools/build_site_replica.py`) remain in the
  repository for a learning-unit page, where a picture of a real shell
  session earns its place. The `figure.replica` CSS is still here for
  that.

- The web fonts are Public Sans subsets built by
  `tools/build_site_fonts.py` from the locally installed faces. The
  licence ships beside them and the build refuses to run without it.
  The stylesheet lists `local()` sources first, so a visitor who
  already has the font downloads nothing.

```
python tools/build_site_pages.py
python tools/build_site_figures.py --og
python tools/build_site_fonts.py
```

## Security

The site's main defence is having almost nothing to attack.

- No JavaScript, no cookies, no third-party requests. Every asset is
  served from the same origin, the fonts included.

- A Content-Security-Policy `<meta>` tag sets `default-src 'none'`,
  with images, styles and fonts limited to `'self'`, plus
  `base-uri 'none'` and `form-action 'none'`. The policy forbids inline
  styles and scripts, so the pages use none.

- Referrer-Policy is `no-referrer`, so outbound clicks carry no URL
  data.

GitHub Pages serves static files and [does not support custom response
headers](https://github.com/orgs/community/discussions/54257). Two
honest limits follow.

- `frame-ancestors` cannot be set. MDN documents that the directive is
  ignored in a `<meta>` policy, and Pages cannot send the header. The
  risk is low for a content-only site with no logged-in state, but it
  is a real gap.

- HSTS, `X-Content-Type-Options` and `Permissions-Policy` are
  unavailable for the same reason. "Enforce HTTPS" in the Pages
  settings covers the redirect half of what HSTS would do.

If the site later moves to a host that can send headers, add these and
drop the two `<meta>` tags in their favour:

```
Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

## Custom domain, in the safe order

The domain also carries the project's mailbox. Only ever add records;
never change MX or existing TXT records.

1. **Verify the domain first.** GitHub account settings, Pages, add
   `groundedaipractice.co.uk` as a verified domain. Add the TXT record
   GitHub specifies at the DNS host, wait for it to propagate, verify.
   Keep the record afterwards. An [unverified domain can be claimed by
   someone
   else](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)
   if it ever comes unlinked.

2. **Point DNS.** Four `A` records on the bare domain to GitHub's
   Pages addresses, and a `www` CNAME to `ohps-stack.github.io`. Never
   use the registrar's domain forwarding for this; it breaks HTTPS.

3. **Attach and encrypt.** Set the custom domain in the repository's
   Pages settings, wait for the DNS check and the certificate, then
   tick "Enforce HTTPS". Update `canonical` and the `og:` URLs in
   `index.html` to the domain.

## Accessibility

Semantic landmarks, a skip link, one `h1`, headings in order, alt text
carrying each figure's data, and visible focus outlines. The diagrams
are HTML rather than drawn images, so their text scales, wraps and
reads to a screen reader like any other text.
`tools/build_site_figures.py` audits every palette pair the site
relies on against WCAG 2.1 AA and refuses to build on a failure; the
printed ratios are the site's accessibility record. Dark mode follows
the visitor's system setting. There is no toggle, because a toggle
needs JavaScript the site otherwise has no reason to carry.

## Adding a learning unit

The pilot unit can live here when it is ready: a `learn/` folder
beside `index.html`, same stylesheet, same components. The callout,
flow and card styles are the unit's visual language already, so a unit
page needs no new tooling. A static page also collects nothing from a
learner, which keeps the trial's data-protection questions where they
belong: with the trial, not the site. Publishing anything there stays
a per-item decision.
